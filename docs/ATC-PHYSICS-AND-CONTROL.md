# 仿真节奏、许可自由度与地面运动改造

日期：2026-10-18。对应游戏目录 `atc-sim/`。

## 核验结果

| 反馈 | 原因与差距 | 本轮实现 |
|---|---|---|
| 1× 也过快 | `TIME_SCALE = 6`，所有移动、减速、通话等待都被压缩。45 分钟班次只用 7.5 现实分钟 | 1× 改为实时；保留 2×、4×、暂停及下一请求 |
| 许可过度受限 | 物理占用、另一架的落地预留、尾流、计划顺序、天气、检查与预计窗口都使用同一拒绝接口 | 顶栏「风险保护」开关，默认关闭。开启：风险拒绝；关闭：风险警告、允许决定，实际碰撞或冲出跑道失败 |
| 降落像急刹 | 6 倍速放大减速感；接地硬截 140 kt、瞬间对正；在入口就接地，没有入口高度与拉平；脱离时瞬转 90°、跳位置及速度 | 入口约 15 m、250 m 拉平段；保留接地速度与航向；制动从 0.4 渐进至 2.2 m/s²；航向、横向偏差及脱离路径连续变化 |
| 空地物理混用 | `gs` 名为地速，空中积分却再加风；抬轮仍按无风地速判断 | 地速直接积分；目标空速转换时纳入顺风/逆风分量，抬轮与估时使用相同转换 |
| 移交没有过程 | `issue()` 立即修改飞机，只把复诵日志延后 2.5 秒 | 所有指令先发话、再复诵、最后确认执行；同频道排队，不同频道并行。UI 显示阶段、倒计时和进度 |
| 不能提前移交 | 只有固定阶段与高度才允许点击，确认和真正移交混在一起 | 滑行中可预联系塔台，到等待点生效；跑道外可预移交 DEP，离地且达到 1500 ft 生效；接地后可联系 GND |
| 推出机头打圈 | 机头从开始就追逐最终航向，与移动路径分离；辅助模式走 40 m 就强行结束推出 | 低速曲线牵引，机头沿反向路径切线变化；完整到达机坪后结束，两种模式共用路径；停止时不原地旋转 |
| 路网过密、左侧不连通 | P/A、B、C 三条平行路，东侧额外回环；最西出口只有 x=-400 | 保留 A 进场西向、B 离场东向；删除 C 和东回环，保留必要的西侧闭环；补 A4，距入口 2100 m，连接 x=-900 |
| 滑行没有跟车感 | 整段滑行道独占，后机常在很远处瞬停 | 同向共享路段，按前机速度、机身长度、间距和制动距离调速；前机停止后自动停，通行后自动恢复；仅路口预约 |

其他 agent 的观察中，6 倍时钟、瞬时接地跳变和 C 路冗余判断成立；但只改为 3 倍仍会压缩运动，只延迟移交不解决其他动作，推出到位后原地转向也不够。渲染还存在硬编码的 C 标牌、地图标签和边灯，不能只删除路网数据。

2.2 m/s² 是可调的游戏制动参数，不能据此认定所有真实机型都合理。真实落地过程还取决于重量、反推、扰流板、轮刹与道面状态。本轮依据 [FAA《Airplane Flying Handbook》第 16 章](https://www.faa.gov/sites/faa.gov/files/regulations_policies/handbooks_manuals/aviation/airplane_handbook/17_afh_ch16.pdf) 对拉平、主轮接地、前轮放下和地面减速的阶段描述，修复连续性；仍使用轻量运动学模型。

## 许可与失败规则

- **保护开启**：物理过近、短五边、占用、尾流、计划、检查和机型风限均可拒绝。进场、滑行及等待指令仍可用于化解风险。实际滑跑迫近障碍时可制动或中断起飞。
- **保护关闭**：这些条件显示警告，允许发出许可；不会因保守预测窗口不足而替玩家刹停或因跑道预留而强制复飞。飞行员仍会因没有落地许可、过高、偏离或超速而复飞。
- **真实失败**：机身/机翼近似碰撞形状相交且高度接近，或撞到当前检查车，或实际冲出跑道。失败后停止仿真、说明具体对象，提供重试及复盘；不会保存成功成绩。
- 有警告的许可可手动点击，不会被 E 键推荐，也不会强迫玩家放行才能推进等待。地面自动跟车与路口让行是两种模式共同的驾驶行为。关闭保护允许玩家承担起降许可风险，不会关闭飞机自身的滑行跟车。
- 依然拒绝非法参数、错误阶段及已移交 DEP 后的本席命令。这些是动作无法执行的前置条件。

## 无线电与提前移交

每条有效命令保存 `startsAt / readbackAt / commitAt`，依据文本长度计算固定仿真时间。完整复诵前飞机继续执行旧许可，停放飞机不会先动起来。同一飞机通话中不重复接收命令，同一频道不会同时发两条话。

确认时重新核验当前状态和安全模式；例如保护开启时，通话中跑道进入检查，尚未确认的起飞许可就不会生效，并在无线电与提示中说明原因。暂停会暂停通话；继续或推进下一请求后恢复。

提前移交的确认与生效分开：确认后的 DEP 预移交只占用 `pendingHandoff`，不占用命令通话槽，塔台仍可正常给予进跑道及起飞许可。达到条件后只切换一次席位、只计一次移交。复飞会清掉过期预移交。

声音目前仍是本地提示音，通话完成以文本发话及复诵进度为准；没有把操作系统语音播报的完成事件当成仿真时钟。

## 路网与跟车实现注意事项

1. A 道节点保留内部 P 前缀，界面统一显示 A；B 为第二条平行道。机位联络道及四条跑道脱离口不计作额外平行滑行道。
2. A4 到任意机位均有有向路线：需要时经西端联络道回到东向 B 道。东端只保留 B1090 → P1090 → LINEUP。
3. 推出、进跑道及脱离采用曲线；三维道面与地面图使用相同控制点。普通路口在道面内圆滑转弯，保留原图节点用于预约。
4. 跟车跨越中间图节点持续有效；只有下一段真正转向时，才排除转弯之后的前方车辆，防止误跟另一支路及漏看同向前机。
5. 交叉口等待距离考虑双方机身尺寸，避免宽体机机翼擦过停在支路口的飞机。前车占据路口时后车不抢占该节点。
6. 跑道使用者从实际状态派生，不再靠覆盖一个占用 ID 隐藏前机；快照保留全部使用者。

## 实施与验收顺序

1. 核验基线及已有参考克隆，保留现有 Git 历史。
2. 调整时钟，拆分风险提示与许可拒绝，接入安全开关及失败结算。
3. 加入确定性的通话事务与提前移交，接入进度 UI、快照和回放。
4. 修复接地速度、拉平、渐进制动、航向及脱离轨迹，校正地速和抬轮风分量。
5. 重做推出，精简双滑行道，补西出口与渲染标牌，建立自动跟车及路口让行。
6. 运行窗口的 AT72 提前至第 6.5 分钟请求推出，确保完整推出、滑行和通话后仍在阵风期间等待。保留同种子的原始班表随机序列；挑战班次改为 45 分钟，离场目标时刻改为请求后 8 分钟，适应完整牵引、滑行及无线电时间。
7. 旧拒绝测试显式启用保护；旧同步指令测试等待真实复诵 tick，不添加运行时跳过确认的特例。新增控制、物理与跟车测试，以及原生浏览器开关/警告/通话/失败/手机验证。

回放规则升级到版本 2，记录起始安全模式及班内切换，包含通话中间状态。旧物理版本不会被静默当作当前规则重放。旧 `taxi.route = bypass` 命令仍作为主路别名接受，已删除的 C 路点不会被编造成不存在的路。

## 本轮验证

- `npm run accept`：九组，133 项逻辑验收；包含 128 份种子班表、28 个完整种子班次、18 组密集波次，以及全部关卡与调度回放。
- `npm run control:ui:test`：原生按钮验证开关持久保存、同一风险两种模式、完整复诵后执行、提前 DEP 移交、实际碰撞失败、双道地图及手机布局。
- 受影响的标准进离场、运行窗口与调度决策 UI 回归另行检查。

后续物理工作可以加入机型制动档位、湿跑道、反推/扰流板动画、更多牵引方向与车轮转角；完整气动、侧风漂移与重量/推力积分不属于当前运动学模型。
