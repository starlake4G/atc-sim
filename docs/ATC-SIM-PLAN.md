## 1. 项目定位

**一句话**：浏览器打开就能玩的双视角机场管制模拟器 —— 门槛最低，但机制不打折。

### 1.1 差异化（经竞品调研修正）

原方案把"双视角"当卖点，**这是错的**。PC 端的 Tower! Simulator 3、移动端的 Unmatched ATC 早就是双视角，2026 年 9 月刚发行的 Airport Control 27 更是把拟真做到 1:1。

修正后的差异化：**Web 端零门槛 + 双视角 + 中等拟真**。

现有 Web 端产品（atc-sim.com、ProjectATC）全是 2D 雷达或休闲画线，**没有成熟的"3D 塔台 + 2D 雷达"产品**。这是唯一清晰的空位。

### 1.2 目标人群

"好奇但没入门的大多数"，不是硬核模拟玩家。硬核玩家抢不过 Endless ATC。

### 1.3 三条从竞品失败中学到的纪律

| 纪律 | 起因 |
|---|---|
| **不做货币化进度系统**，所有内容直接开放 | UATC 因"金币解锁机场"被大量差评 |
| **鼠标键盘优先，语音不作为核心机制** | Tower!3 的语音识别对非母语口音表现很差 |
| **渐进式引导**，第一关只教一架飞机 | Tower!3 没有教程，被批"不翻 PDF 玩不下去" |

### 1.4 明确不做（第一期）

多人协同管制 / 真实航图全量导入 / 完整飞行力学 / 移动端触屏适配 / 语音识别下达指令。

## 3. 架构

```
┌──────────────────────────────────────────────────┐
│ View Layer（可插拔）                               │
│   RadarView(2D)   SceneView(3D)   ViewHost        │
├──────────────────────────────────────────────────┤
│ Command / Input Layer（一套指令 UI，两视图共用）     │
├──────────────────────────────────────────────────┤
│ World Model（唯一真值源）                           │
├──────────────────────────────────────────────────┤
│ Sim Core（纯逻辑，零渲染依赖，20Hz 定步长）           │
│   飞机状态机 · 指令执行 · 冲突检测 · 交通生成 · 计分    │
└──────────────────────────────────────────────────┘
```

### 3.1 五条硬约定（破了必返工）

1. **Sim Core 不许 `import three`** —— 保持可单测、可无头运行
2. **视图只读快照**，绝不回写世界状态
3. **定步长 + 累积器** —— 逻辑固定 20Hz，渲染自由帧率；时间倍速只改 tick 累积量
4. **内部一律 SI**（米 / 米每秒），英尺·节·海里只在显示层转换
5. **View 接口固定**：`mount(container)` / `update(snapshot, dt)` / `unmount()`

> **2026-09-28 复核：红线 1/3/4 守住，2/5 有偏差，需要么补代码要么改本表。**
> - 红线 1 ✅：`three` 只出现在 `views/scene.ts` 与 `views/daycycle.ts`。
> - 红线 3 ✅：定步长 + 累积器，单帧 realDt 夹 0.25 s、`MAX_STEPS_PER_FRAME` 防螺旋。
> - 红线 4 ⚠️：仍有裸字面量绕过 `units.ts` —— `views/radar.ts` 三处 `* 1852`、`sim/world.ts` 的 `worldStats()` 用 `/ 0.514444` 并把 kt/NM 显示值放进 sim 层函数；`formatAltitude()`/`formatNm()` 反而零调用，标牌 `FL0xx` 在 radar 与指令条里各手搓一遍。
> - 红线 2/5 ⚠️：**没有快照层**。`radar.update(world)` / `scene.update(world)` 直接读活的 `World`，也没有 `dt` 形参；`unmount()` 三方都实现了但无人调用（§8.2 已记"无 host 层"）。视图本身没回写（选中经 `onSelect` 回调交给 `main.ts`），但 `ui/list.ts` 直接写 `world.selectedId`。要么补 `Readonly<World>`/快照类型并统一走 Command/Input，要么把第 2/5 条按现实改写。

### 3.2 双视角的定位（2026-09-28 改版：3D 为主舞台）

**主舞台固定 16:9**（1600×900 虚拟分辨率排版，整体 `transform: scale` 贴合窗口）——
3D 视景是按 16:9 做的构图，窗口比例一变要么裁掉跑道要么留大片空地；
UI 按固定虚拟分辨率排版也顺手消灭了"窄窗口下 HUD 和侧栏互相挤出去"这一类问题。

| 视角 | 定位 | 呈现 |
|---|---|---|
| 3D 塔台视景（默认） | **主视图**：空间感、排队/落地/复飞看得见 | 铺满舞台，飞机带 HTML 标牌（呼号/高度/趋势/速度，冲突红、选中白） |
| 3D 跟机视角 | 检查、欣赏、复盘 | 铺满舞台，标牌同上 |
| 2D 雷达屏 | 精修引导时用 | 舞台左上 300×300 小窗（`M` 键开关），`F1` 放大成全屏铺满 |

侧栏（飞机列表 + 无线电记录）与指令条都是舞台内的浮层，不再是浏览器页面的一部分。

**切视角 = 换相机 + 换叠放，不是换游戏。** 指令链路、世界状态、计分完全共用，
两个视图读同一个 `World`。

## 4. 坐标与单位约定（实现依据）

- **坐标系**：局部 ENU 平面，原点 = 机场中心，忽略地球曲率（雷达管制本就是平面投影）
  - `x` = 东（米） / `y` = 北（米） / `z` = 高度（米）
- **航向**：度，`0` = 正北，顺时针增加
- **风向**：度，表示**来向**（气象惯例）；气流去向 = 风向 + 180
- **风的影响**：地速向量 = 空速向量（沿航向）+ 风向量

## 6. 玩法设计

### 6.1 核心循环

```
流量生成 → 玩家下达指令 → 飞行员复诵并执行（有延迟、有惯性）
   ↑                                          ↓
   └──── 计分结算 ←── 冲突/落地/起飞事件 ←── 世界按 20Hz 演进
```

### 6.2 指令集（MVP 闭环，已实现）

| 类别 | 指令 |
|---|---|
| 雷达引导 | `HDG 000–360`、`TURN LEFT/RIGHT`、`DIRECT <fix>` |
| 高度 | `ALT`（升降并保持）、`EXPEDITE` |
| 速度 | `SPD`、`RESUME NORMAL SPEED` |
| 进近 | `ILS APP RWY xx`、`GO AROUND`、`HOLD AT <fix>` |
| 地面 | `CLEARED FOR TAKEOFF`（跑道外等待 → 起飞滑跑）；滑行/推出属 P2 地面管制域，未实现 |

### 6.3 计分与自适应难度

**技能分 = 可同时管制的飞机数上限**（Endless ATC 的验证过设计）：4 架起步，每 12 分升 1 架，封顶 18。
真正的节流阀是"在场上限"（容量 + 2 余量），流率故意给满，一空下来立刻补一架 —— 保证手上一直有事。

- 加分：落地 12（落对指定跑道 +6）、起飞 6、**连击**（连续无违规落地每架再 +3，最多 5 档，任何一次扣分归零）
- 扣分：严重冲突 5、失去间隔 15、复飞 4、飞出扇区 8、落错跑道 5
- **只提示不扣分**：预测级冲突（300 s 前瞻）、跑道被占导致的驳回（直接不生效 + 电台说明）
- 反馈层：落地/起飞在舞台中央弹字、吃牌时黄/红牌闪动、容量提升弹提示、HUD 显示游戏内钟表
  （1 现实分钟 = 1 游戏小时，07:30 开局）

### 6.4 机场数据驱动

机场用数据描述（跑道/航路点/扇区/STAR/SID），加机场 = 加一个数据文件。
