## 1. 项目定位

**一句话**：浏览器打开就能玩的双视角机场管制模拟器 —— 门槛最低，但机制不打折。

### 1.1 差异化（经竞品调研修正）

原方案把"双视角"当卖点，**这是错的**。PC 端的 Tower! Simulator 3、移动端的 Unmatched ATC 早就是双视角，2026 年 9 月刚发行的 Airport Control 27 更是把拟真做到 1:1。

修正后的差异化：**Web 端零门槛 + 双视角 + 中等拟真**。

现有 Web 端产品（atc-sim.com、ProjectATC）全是 2D 雷达或休闲画线，**没有成熟的"3D 塔台 + 2D 雷达"产品**。这是唯一清晰的空位。

### 1.2 目标人群

"好奇但没入门的大多数"，不是硬核模拟玩家。硬核玩家抢不过 Endless ATC。

### 1.3 三条从竞品失败中学到的纪律

| 纪律 | 起因 |
|---|---|
| **不做货币化进度系统**，所有内容直接开放 | UATC 因"金币解锁机场"被大量差评 |
| **鼠标键盘优先，语音不作为核心机制** | Tower!3 的语音识别对非母语口音表现很差 |
| **渐进式引导**，第一关只教一架飞机 | Tower!3 没有教程，被批"不翻 PDF 玩不下去" |

### 1.4 明确不做（第一期）

多人协同管制 / 真实航图全量导入 / 完整飞行力学 / 移动端触屏适配 / 语音识别下达指令。

## 3. 架构

```
┌──────────────────────────────────────────────────┐
│ View Layer（可插拔）                               │
│   RadarView(2D)   SceneView(3D)   ViewHost        │
├──────────────────────────────────────────────────┤
│ Command / Input Layer（一套指令 UI，两视图共用）     │
├──────────────────────────────────────────────────┤
│ World Model（唯一真值源）                           │
├──────────────────────────────────────────────────┤
│ Sim Core（纯逻辑，零渲染依赖，20Hz 定步长）           │
│   飞机状态机 · 指令执行 · 冲突检测 · 交通生成 · 计分    │
└──────────────────────────────────────────────────┘
```

### 3.1 五条硬约定（破了必返工）

1. **Sim Core 不许 `import three`** —— 保持可单测、可无头运行
2. **视图只读快照**，绝不回写世界状态
3. **定步长 + 累积器** —— 逻辑固定 20Hz，渲染自由帧率；时间倍速只改 tick 累积量
4. **内部一律 SI**（米 / 米每秒），英尺·节·海里只在显示层转换
5. **View 接口固定**：`mount(container)` / `update(snapshot, dt)` / `unmount()`

### 3.2 双视角的定位（不可动摇）

| 视角 | 定位 | 交互权重 |
|---|---|---|
| 2D 雷达屏 | 主交互面，所有指令在这里下 | 90% |
| 3D 塔台视景 | 空间感与紧迫感，看得见排队/落地/复飞 | 5% |
| 3D 跟机视角 | 检查、欣赏、复盘 | 5% |

**切视角 = 换相机 + 换 UI 层，不是换游戏。**

## 4. 坐标与单位约定（实现依据）

- **坐标系**：局部 ENU 平面，原点 = 机场中心，忽略地球曲率（雷达管制本就是平面投影）
  - `x` = 东（米） / `y` = 北（米） / `z` = 高度（米）
- **航向**：度，`0` = 正北，顺时针增加
- **风向**：度，表示**来向**（气象惯例）；气流去向 = 风向 + 180
- **风的影响**：地速向量 = 空速向量（沿航向）+ 风向量

## 6. 玩法设计

### 6.1 核心循环

```
流量生成 → 玩家下达指令 → 飞行员复诵并执行（有延迟、有惯性）
   ↑                                          ↓
   └──── 计分结算 ←── 冲突/落地/起飞事件 ←── 世界按 20Hz 演进
```

### 6.2 指令集（MVP 闭环，已实现）

| 类别 | 指令 |
|---|---|
| 雷达引导 | `HDG 000–360`、`TURN LEFT/RIGHT`、`DIRECT <fix>` |
| 高度 | `ALT`（升降并保持）、`EXPEDITE` |
| 速度 | `SPD`、`RESUME NORMAL SPEED` |
| 进近 | `ILS APP RWY xx`、`GO AROUND`、`HOLD AT <fix>` |
| 地面 | `CLEARED FOR TAKEOFF`（跑道外等待 → 起飞滑跑）；滑行/推出属 P2 地面管制域，未实现 |

### 6.3 计分与自适应难度

**技能分 = 可同时管制的飞机数上限**（Endless ATC 的验证过设计）。

- 加分：成功落地、成功起飞、间隔合规
- 扣分：冲突告警、间隔不足、复飞、飞出扇区、进错跑道

### 6.4 机场数据驱动

机场用数据描述（跑道/航路点/扇区/STAR/SID），加机场 = 加一个数据文件。

## 10. 已知问题与风险

**本轮已修复**（原 Sim Core 未经运行验证遗留）：

| 问题 | 修复 |
|---|---|
| **起飞滑跑阶段就朝 SID 转向**（用户实测发现：滑跑中航向已到 277°，飞机斜着拐出跑道；停在跑道外的飞机也会原地慢慢转向） | `updateAircraft` 转向链对 GROUND/TAKEOFF 阶段锁死当前航向，升空转 CLIMB 后才交给 SID 引导 |
| **滑跑中飞机会被侧风吹离跑道中线** | `integrate` 地面阶段（等待/滑跑/落地滑跑）沿机头方向纯滚动（机轮约束），不叠加风漂移 |
| 跟机相机换选中目标时从旧机位慢速漂移 | 记录 `lastFollowId`，换目标即 `snapNextFrame` 直接就位 |
| 塔台机位 (y=88) 落在塔身圆筒内，塔冠底盖 (y=92) 挡住上半视野 | 机位抬进塔冠玻璃环内 (y=96)（P1 期间发现） |
| `steerRoute` 多航路点绕点死循环（提前转弯不推进 routeIndex） | 改为"地速与指向当前点方向点积 < 0（越过切点）即推进"，单调且抗风 |
| `localizerCapture` 截获夹角取反（对正判成 180°，永远截获不了） | 删除 `180 - angle` 反转 |
| 下滑道跟随纯比例控制存在 ~30m 余差，飞机永远差一点"接地" | 改为前馈（沿跑道地速 × 下滑角）+ 比例消余差，符号已核对 |
| 停机等待的飞机会被 clamp 抬到最小速度"自飞"并被风吹走 | `takeoffCleared` 区分等待/滑跑；未许可时不推进物理 |
| 雷达 mouseup 挂在 window 上，点侧栏按钮会清掉选中 | 仅"画布上按下且抬起"才拾取 |
| STAR 航路包含出生点自身，配合转弯逻辑卡死 | 进场航路 slice(1) 跳过入口 fix |
| 起飞滑跑加速度过慢（A388 需 96s 才抬轮） | 加减速表提升到 2.5–4.0 kt/s |

**仍然存在**：

| 问题 | 影响 | 处置 |
|---|---|---|
| 等待航线入航段逻辑偏简化（用相对位置切段） | 低 | 按真实入航方法（直接/偏置/平行入航）细化 |
| 冲突检测 O(n²) | 低 | 百架量级无压力，暂不优化 |
| 机型性能表为估算值 | 低 | 影响手感不影响正确性，后续按需标定 |
| 进场初始高度 5000–7500m（原定 FL200–FL300） | 低 | 为保证下降剖面可玩性下调，标注"本项目"来源 |
| 简易自动管制员（冒烟测试用）不会排序进近，冲突扣分多 | 仅测试 | 断言只要求机制指标，不要求 bot 得分 |
| `npm run dev` 在 5173 被其他应用占用时会顺延到 5174 | 低 | 启动时看终端提示的实际端口 |

## 11. 运行方式

```bash
cd atc-sim
npm install        # 已完成
npm run typecheck  # 类型检查
npm run dev        # 开发服务器（默认 5173，被占用时自动顺延）

```

Sim Core 无头测试（不需要浏览器，20 项断言验证运动学/指令/进近/冲突全流程）：

```bash
cd atc-sim
npm run sim:test
```

> 玩法：进场机沿 STAR 自动进场，需要下高度、雷达引导、清 ILS 进近；离场机给「可以起飞」后沿 SID 爬升，出扇区即移交加分。
