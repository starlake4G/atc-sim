## 1. 项目定位

**一句话**：浏览器打开就能玩的双视角机场管制模拟器 —— 门槛最低，但机制不打折。

### 1.1 差异化（经竞品调研修正）

原方案把"双视角"当卖点，**这是错的**。PC 端的 Tower! Simulator 3、移动端的 Unmatched ATC 早就是双视角，2026 年 9 月刚发行的 Airport Control 27 更是把拟真做到 1:1。

修正后的差异化：**Web 端零门槛 + 双视角 + 中等拟真**。

现有 Web 端产品（atc-sim.com、ProjectATC）全是 2D 雷达或休闲画线，**没有成熟的"3D 塔台 + 2D 雷达"产品**。这是唯一清晰的空位。

### 1.2 目标人群

"好奇但没入门的大多数"，不是硬核模拟玩家。硬核玩家抢不过 Endless ATC。

### 1.3 三条从竞品失败中学到的纪律

| 纪律 | 起因 |
|---|---|
| **不做货币化进度系统**，所有内容直接开放 | UATC 因"金币解锁机场"被大量差评 |
| **鼠标键盘优先，语音不作为核心机制** | Tower!3 的语音识别对非母语口音表现很差 |
| **渐进式引导**，第一关只教一架飞机 | Tower!3 没有教程，被批"不翻 PDF 玩不下去" |

### 1.4 明确不做（第一期）

多人协同管制 / 真实航图全量导入 / 完整飞行力学 / 移动端触屏适配 / 语音识别下达指令。

## 3. 架构

```
┌──────────────────────────────────────────────────┐
│ View Layer（可插拔）                               │
│   RadarView(2D)   SceneView(3D)   ViewHost        │
├──────────────────────────────────────────────────┤
│ Command / Input Layer（一套指令 UI，两视图共用）     │
├──────────────────────────────────────────────────┤
│ World Model（唯一真值源）                           │
├──────────────────────────────────────────────────┤
│ Sim Core（纯逻辑，零渲染依赖，20Hz 定步长）           │
│   飞机状态机 · 指令执行 · 冲突检测 · 交通生成 · 计分    │
└──────────────────────────────────────────────────┘
```

### 3.1 五条硬约定（破了必返工）

1. **Sim Core 不许 `import three`** —— 保持可单测、可无头运行
2. **视图只读快照**，绝不回写世界状态
3. **定步长 + 累积器** —— 逻辑固定 20Hz，渲染自由帧率；时间倍速只改 tick 累积量
4. **内部一律 SI**（米 / 米每秒），英尺·节·海里只在显示层转换
5. **View 接口固定**：`mount(container)` / `update(snapshot, dt)` / `unmount()`

> **2026-09-28 复核：红线 1/3/4 守住，2/5 有偏差，需要么补代码要么改本表。**
> - 红线 1 ✅：`three` 只出现在 `views/scene.ts` 与 `views/daycycle.ts`。
> - 红线 3 ✅：定步长 + 累积器，单帧 realDt 夹 0.25 s、`MAX_STEPS_PER_FRAME` 防螺旋。
> - 红线 4 ⚠️：仍有裸字面量绕过 `units.ts` —— `views/radar.ts` 三处 `* 1852`、`sim/world.ts` 的 `worldStats()` 用 `/ 0.514444` 并把 kt/NM 显示值放进 sim 层函数；`formatAltitude()`/`formatNm()` 反而零调用，标牌 `FL0xx` 在 radar 与指令条里各手搓一遍。
> - 红线 2/5 ⚠️：**没有快照层**。`radar.update(world)` / `scene.update(world)` 直接读活的 `World`，也没有 `dt` 形参；`unmount()` 三方都实现了但无人调用（§8.2 已记"无 host 层"）。视图本身没回写（选中经 `onSelect` 回调交给 `main.ts`），但 `ui/list.ts` 直接写 `world.selectedId`。要么补 `Readonly<World>`/快照类型并统一走 Command/Input，要么把第 2/5 条按现实改写。

### 3.2 双视角的定位（不可动摇）

| 视角 | 定位 | 交互权重 |
|---|---|---|
| 2D 雷达屏 | 主交互面，所有指令在这里下 | 90% |
| 3D 塔台视景 | 空间感与紧迫感，看得见排队/落地/复飞 | 5% |
| 3D 跟机视角 | 检查、欣赏、复盘 | 5% |

**切视角 = 换相机 + 换 UI 层，不是换游戏。**

## 4. 坐标与单位约定（实现依据）

- **坐标系**：局部 ENU 平面，原点 = 机场中心，忽略地球曲率（雷达管制本就是平面投影）
  - `x` = 东（米） / `y` = 北（米） / `z` = 高度（米）
- **航向**：度，`0` = 正北，顺时针增加
- **风向**：度，表示**来向**（气象惯例）；气流去向 = 风向 + 180
- **风的影响**：地速向量 = 空速向量（沿航向）+ 风向量

## 6. 玩法设计

### 6.1 核心循环

```
流量生成 → 玩家下达指令 → 飞行员复诵并执行（有延迟、有惯性）
   ↑                                          ↓
   └──── 计分结算 ←── 冲突/落地/起飞事件 ←── 世界按 20Hz 演进
```

### 6.2 指令集（MVP 闭环，已实现）

| 类别 | 指令 |
|---|---|
| 雷达引导 | `HDG 000–360`、`TURN LEFT/RIGHT`、`DIRECT <fix>` |
| 高度 | `ALT`（升降并保持）、`EXPEDITE` |
| 速度 | `SPD`、`RESUME NORMAL SPEED` |
| 进近 | `ILS APP RWY xx`、`GO AROUND`、`HOLD AT <fix>` |
| 地面 | `CLEARED FOR TAKEOFF`（跑道外等待 → 起飞滑跑）；滑行/推出属 P2 地面管制域，未实现 |

### 6.3 计分与自适应难度

**技能分 = 可同时管制的飞机数上限**（Endless ATC 的验证过设计）。

- 加分：成功落地、成功起飞、间隔合规
- 扣分：冲突告警、间隔不足、复飞、飞出扇区、进错跑道

### 6.4 机场数据驱动

机场用数据描述（跑道/航路点/扇区/STAR/SID），加机场 = 加一个数据文件。

## 10. 已知问题与风险

**2026-09-28 复核修复（P0 主玩法链路）** —— 这一批是"文档说完成、实际跑不通"的根因：

| 问题 | 修复 |
|---|---|
| **`steerRoute` 绕点死循环**：提前转弯触发半径（`turnRadius × 1.2` ≈ 2.5 NM）远大于到点判定阈值（2 秒航程 ≈ 0.15 NM），飞机绕着 STAR 首点无限盘旋，`routeIndex` 永远不推进（实测 40 分钟距场 35–40 NM 来回振荡） | 改为"地速与指向当前点向量点积转负（越过切点）即推进"，索引单调不回退；提前拐向下一点时同时推进索引 |
| **交通生成 bootstrap 死锁**：开局预置 3 架正好占满 `capacity=3` 的生成上限，`updateTraffic` 首行直接 return，场地从此零生成 | 生成上限改为 `capacity + SPAWN_HEADROOM(2)`，HUD 显示"在场 x/上限" |
| **指令条 ILS 门控自锁**：`ui/commands.ts` 只在 `phase === 'APPROACH'` 时渲染进近许可按钮，而 APPROACH 阶段本身要靠这条许可才会进入 → 玩家永远点不到 | 抽出 `canClearApproach(ac)` 判据（进场航班且已在空中，含复飞），并把"已建立 ILS 只留复飞"的收拢条件从横向建立改为 `slopeCaptured`；LANDED/TAKEOFF 判定提前于收拢判定 |
| **进近剖面追不上只能冲过跑道头**：下滑道按比例硬跟，FL240 被清进来时一路用满下降率仍追不上；且飞越跑道头后航向道失锁、纯追踪又把目标点拖到身后，飞机绕入口无限盘旋（既不离开扇区也不再受控，永久吃掉交通名额） | 加 1000 ft 截获窗口（远高于剖面时保持玩家给定高度，剖面交给玩家）；偏低时修正量放开到满爬升率（原来 ±3.5 m/s 补不回来）；飞越跑道头仍未接地则自动复飞；建立下滑道后飞行员自行收到进近速度 |
| **`issueCommand` 连点即失效**：同族同值指令每次重新排队，`executeAt` 被一次次推后，指令永远执行不了 | 队列里已有同族同值指令时保留原条目，不再重新排队 |

**本轮已修复**（原 Sim Core 未经运行验证遗留）：

| 问题 | 修复 |
|---|---|
| **起飞滑跑阶段就朝 SID 转向**（用户实测发现：滑跑中航向已到 277°，飞机斜着拐出跑道；停在跑道外的飞机也会原地慢慢转向） | `updateAircraft` 转向链对 GROUND/TAKEOFF 阶段锁死当前航向，升空转 CLIMB 后才交给 SID 引导 |
| **滑跑中飞机会被侧风吹离跑道中线** | `integrate` 地面阶段（等待/滑跑/落地滑跑）沿机头方向纯滚动（机轮约束），不叠加风漂移 |
| 跟机相机换选中目标时从旧机位慢速漂移 | 记录 `lastFollowId`，换目标即 `snapNextFrame` 直接就位 |
| 塔台机位 (y=88) 落在塔身圆筒内，塔冠底盖 (y=92) 挡住上半视野 | 机位抬进塔冠玻璃环内 (y=96)（P1 期间发现） |
| `steerRoute` 多航路点绕点死循环（提前转弯不推进 routeIndex） | 改为"地速与指向当前点方向点积 < 0（越过切点）即推进"，单调且抗风 |
| `localizerCapture` 截获夹角取反（对正判成 180°，永远截获不了） | 删除 `180 - angle` 反转 |
| 下滑道跟随纯比例控制存在 ~30m 余差，飞机永远差一点"接地" | 改为前馈（沿跑道地速 × 下滑角）+ 比例消余差，符号已核对 |
| 停机等待的飞机会被 clamp 抬到最小速度"自飞"并被风吹走 | `applySpeed` 对地面阶段放开速度下限到 0 + `updateAircraft` 对 GROUND 锁航向（本基干**没有** `takeoffCleared` 字段，靠 phase 表达）。注意 sim 层仍不拒绝给 GROUND 机下速度/航向指令，只靠指令条不显示按钮兜底 |
| 雷达 mouseup 挂在 window 上，点侧栏按钮会清掉选中 | 仅"画布上按下且抬起"才拾取 |
| STAR 航路包含出生点自身，配合转弯逻辑卡死 | 本基干改为在入口 fix 外 8–14 NM 出生、航路保留首点（不 slice）；真正的绕点卡死见上方 2026-09-28 复核表 |
| 起飞滑跑加速度过慢（A388 需 96s 才抬轮） | 已修，但机制与旧记录不同：本基干用 `GROUND_ACCEL = 4.5 kt/s`（`aircraft.ts`）专管滑跑，机型表里的 accel/decel 仍是 0.8–1.5 kt/s 且只用于空中 |

**仍然存在**：

| 问题 | 影响 | 处置 |
|---|---|---|
| 等待航线入航段逻辑偏简化（用相对位置切段） | 低 | 按真实入航方法（直接/偏置/平行入航）细化 |

| 机型性能表为估算值 | 低 | 影响手感不影响正确性，后续按需标定 |

| 雷暴是占位数据：`createWorld({storm:true})` 塞的是 `radius:1 m`、原点单体，且没有任何开关入口 | 低 | `weather.makeStorm()` 才是正解，但它内部有一处畸形表达式（首航路点 x 为 0 时会把雷暴经度硬置 0）。§11 里"R 开关雷暴"从未实现 |
| 19 个 export 零引用（`sectorAt`/`wakeSeparation`/`recommendRunway`/`formatAltitude`/`makeStorm` 等），`hasBeenControlled` 只写不读 | 低 | `noUnusedLocals` 抓不到 export。要么接入（扇区判定、尾流排序、跑道构型都是设计上要的），要么删掉 |
| 视图层资源与状态回收：`prevPhase` 不删条目；`scene.ts` 每架机新建 7 个 Geometry + 3 个材质但移除时不 `dispose()`；`ui/list.ts` 的 `.al-body` 没有样式（列表长了不滚动） | 低 | 长对局会稳定泄漏；P2 前顺手清 |

## 11. 运行方式

```bash
cd atc-sim
npm install        # 已完成
npm run typecheck  # 类型检查
npm run dev        # 开发服务器（默认 5173，被占用时自动顺延）
npm run build      # 生产构建（tsc --noEmit && vite build）
```

Sim Core 无头测试（不需要浏览器，30 项断言：部件级验证运动学/指令/进近/冲突，链路级验证航路推进、交通生成与"按指令条门控判据能完成一次落地"）：

```bash
cd atc-sim
npm run sim:test
```

> 页面快捷键：`空格` 暂停 · `1`/`2`/`4` 时间倍速 · `F1`/`F2`/`F3` 切换雷达/塔台/跟随 · `Tab` 循环选机 · `Esc` 取消选中 · `R` 复位雷达视图（缩放平移归零）· URL 加 `?view=tower|follow` 直达视角。**雷暴目前没有开关**（`createWorld({storm})` 是占位数据，见 §10）。
> 玩法：进场机沿 STAR 自动进场，需要下高度、雷达引导、清 ILS 进近；离场机给「可以起飞」后沿 SID 爬升，出扇区即移交加分。
