# Kestrel Approach：成品试玩版路线图

更新：2026-10-18。本文是下一阶段建议，不代表下列功能已经实现。

## 1. 下一阶段目标

把当前系统收束为一款可以交给陌生玩家独立游玩的 ATC 试玩版。玩家能完成「进入游戏 → 学会判断 → 接班 → 调度与恢复 → 复盘 → 再开一班」，中途关闭后可以继续。

建议首个发布范围：一座有完整视觉与声音表现的机场、三段互动训练、六个具有不同决策主题的正式班次，以及种子自由挑战。现有八张关卡卡片可重组、重做，不要求额外增加六个同类关卡。

每局正式班次以约 6–10 分钟现实时间为设计起点，允许暂停、加速与推进下一请求。具体长度、密度和难度通过真人试玩调整。

## 2. 当前基础与主要缺口

| 领域 | 当前基础 | 距离成品的缺口 |
| --- | --- | --- |
| 调度 | 手动进离场、路线、移交、尾流与跑道守卫、计划与试排、起飞窗口 | 路线方案代价不够直观；新手很难把系统信息转成自己的判断 |
| 关卡 | 三个训练标记关、固定班次、种子挑战、检查与阵风事件 | 训练主要靠帮助与高亮；部分挑战沿用相同班表调整密度与机型，关卡身份不足 |
| 界面 | 菜单、工作台、可调整面板、移动布局、快捷许可 | 首次进入的信息层级、持续任务提示、交接班仪式和统一设置仍需打磨 |
| 复盘 | 评级、延误归因、逐航班数据、操作回放与导出 | 缺少明确的个人进步反馈、下一项学习目标与资格进度 |
| 保存 | 最佳成绩、画质、窗口布局 | 缺少活动班次保存与继续、完整偏好设置和版本化恢复策略 |
| 表现 | 有比例差异的飞机、起落架/灯光/姿态、机场道面、昼晚景观 | 机场身份、材质与细节层次不足；地勤活动与真实状态联系较弱 |
| 声音 | 可选合成提示音 | 缺少环境、发动机、无线电层次与混音控制 |
| 验证 | 上轮 108 项逻辑回归，浏览器流程与构建通过 | 尚未获得足够的首次玩家理解、节奏和重玩意愿证据 |

## 3. 第一阶段：先做一个完整、易学的班次

### 互动教学

把三段训练改为任务状态机：观察请求 → 理解限制 → 作出选择 → 看到后果 → 独立完成一次。

- 第一课：识别航班、进近与落地许可、脱离和移交；说明每一步的目的。
- 第二课：推出与滑行、等待点、塔台联系、起飞和离场移交。
- 第三课：一架进场与一架离场的顺序选择，实际比较等待与抢先放行的结果。
- 只在当前步骤突出必要信息；完成后逐步显示完整工作台。
- 用仿真事实判定完成，鼠标、快捷键或其他合法操作都可推进，不绑定某个按钮点击。
- 训练末尾撤去直接答案，让玩家独立判断一次。允许重练和直接进入其他模式。

验收：首次玩家不用读长篇说明即可完成三课；错误操作有针对性的解释；暂停、加速、重新开始和合法替代操作不会卡住教学。

### 接班与班次节奏

选择一个旗舰关重做，作为所有系统的体验样板：

1. 接班简报：天气、跑道、流量概况、已知事件、本班目标，进入游戏后仍可查。
2. 开场：少量流量建立机场空间关系，让玩家完成一次完整流程。
3. 主波次：混合机型造成尾流、进离场与地面路线的取舍。
4. 变化：预告一次检查或天气事件，留出可行动的准备时间。
5. 恢复：释放积压、完成末班，清楚显示剩余航班及尚未完成的移交/入位。
6. 收班：沿用实际复盘，强调本班做得最好的决定、一个可改进之处与再次挑战入口。

验收：每段引入新的判断；空档有清楚的下一事件和推进入口；结尾没有不明原因的等待；至少两种合法策略可完成，且代价不同。

### 存档和设置

- 主菜单增加继续值班、新班次、训练、挑战和设置入口。
- 自动保存与手动保存共享版本化数据格式；恢复后暂停，由玩家继续。
- 保存关卡/种子/规则版本、模拟时刻、有效操作和必要运行状态；不能仅保存面板快照。
- 明确处理旧版本、损坏数据、浏览器存储失败；保留其他成绩和设置。
- 切至后台暂停；返回时避免突然累计推进，并同步处理声音。
- 设置统一管理画质、声音分组、界面缩放与操作提示；保留现有窗口布局能力。

验收：在推出、滑行、进近、已许可占跑道及检查期间保存，刷新后资源、许可、计划和后续结果一致。不能因继续游戏重复记分或重复写回成绩。

## 4. 第二阶段：增加可比较、可恢复的策略内容

优先扩展现有机制，让每个新增功能进入具体关卡。

| 新增内容 | 玩家需要决定什么 | 关键验收 |
| --- | --- | --- |
| 主道/旁通路线比较 | 选择更短路线，还是绕开预计拥堵 | 显示路程、估计耗时、阻塞来源；未知明确标注；采用前不改资源 |
| 安全节点改道 | 当前拥堵值得等待，还是改走旁通 | 只在允许节点重新规划；释放旧租约，不倒退穿越其他飞机 |
| 有预告的优先到达 | 为优先航班留窗口时，哪些航班承担延误 | 优先级可读，代价可预判，存在多个安全解法 |
| 有主题的可选目标 | 在安全完成基础上改善尾流、准点或地面效率 | 不奖励冒险，不把主动安全复飞当违规，不只奖励点击速度 |

建议正式班次主题：

1. 晨间交接：完整流程与基本混合排序。
2. 重轻机混流：尾流空档与短窗口的利用。
3. 机坪拥堵：主道/旁通道选择、等待与安全改道。
4. 运行窗口：提前检查与等风，强化现有关的前兆与节奏。
5. 优先到达：重新安排已有计划，并让延误代价可见。
6. 夜间高峰：综合前述能力，使用已熟悉规则形成高峰和恢复。

反向跑道作为后续内容：先补齐进近、复飞、滑行和等待点程序，再制作风向变化任务。双跑道在单跑道的主题关与节奏验证后扩展。

## 5. 第三阶段：统一模型、机场、UI 与声音

### 美术与建模

确定统一的清晰、克制的写实风格。重要细节须在实际塔台/跟随/俯瞰视角中可见。

- 飞机：先完成一架 A320 的参考质量，统一机鼻、座舱玻璃、机翼厚度、翼梢、吊架、起落架比例及材质，再推广其他机型。重型、支线和涡桨保持轮廓差异。
- 涂装：一套完整机身/机尾/航灯语言，扩成少量虚构航空公司；保持远景识别性。
- 机场：统一铺装色阶、接缝/轮迹、道肩、标线、等待点/滑行道标牌、机位编号，先完成主运行区。
- 建筑：用航站楼玻璃、登机桥连接、机库入口和道路尺度建立机场身份；控制重复资产密度。
- 活动：推出时牵引车连接并随动，入位时有指挥/机位提示，停机后地勤到场；活动从真实航班状态产生。
- 镜头：给塔台、跟随和俯瞰分别调整焦点、缩放界限、标签遮挡与选机反馈；天气和暮色变化仍需看清飞机与道面。
- 技术：继续维持合批/实例化，必要时采用细节层级；在目标设备测帧率与内存，不以模型面数或截图作为性能结论。

### UI

- 第一层固定回答：现在谁需要处理、当前被什么阻挡、下一件事何时发生。
- 第二层支持选择：跑道顺序、时间窗口、路线比较、事件准备。
- 第三层提供计算细节、事件记录和深入回放。
- 统一字体、字号、间距、按钮状态、图标与提示语；颜色同时配合文字/形状表达含义。
- 面板开合与许可反馈使用短动画；提供减少动态效果选项。
- 以 1280×720 的完整手动班次验证文本和操作区域；窄屏继续验证事件与采用按钮可达。

### 声音

建立三层基础声音：机场环境、随飞机阶段/距离变化的引擎与滚动、无线电与操作反馈。环境先做白昼与夜间两套密度。

无线电先完成呼叫/回应节奏、轻微静噪及字幕同步，再添加有限句式的语音。声音队列不延迟实际许可，不阻塞玩家后续操作；加速与回放有明确的播放策略。

增加主音量、环境、飞机、无线电和提示音音量。暂停、隐藏页面、退出关卡和切换声音设置时正确收尾，避免叠音和残留音频。

## 6. 第四阶段：形成长期目标并验证发布质量

- 资格进度：用完成训练与掌握调度主题展示成长，挑战模式始终有直接入口。
- 班次勋章：安全完成、准点改善、特定调度目标，避免重复刷次数。
- 个人对比：同一关卡/规则/种子显示本次与最佳成绩差异，并指向可复盘的决定。
- 固定每日/每周种子挑战可在本地生成；规则版本参与记录键，先保证可重复性与公平的个人比较。
- 发布前统一处理加载、空状态、异常恢复、设置保存、资源授权与打包。

玩法分层可参考 [Mini Motorways 官方模式说明](https://dinopoloclub.com/support/mini-motorways/)：不同规则与每日/每周挑战围绕同一核心机制提供重玩理由。本项目需要先验证自己的主题关和评分，再引入类似节奏。

## 7. 真人试玩与发布门槛

以下都是建议目标，需要实测校准，不是当前已有结果。

| 检查 | 建议目标/记录方式 |
| --- | --- |
| 首次理解 | 邀请至少 5 位未玩过项目的人，观察首次有效许可用时、困惑点与需提示次数 |
| 教学完成 | 大多数首次玩家能独立完成训练，再用一班无强制引导任务验证理解 |
| 决策价值 | 玩家能说出至少一次主动等待/改序/改道的理由；同一关存在两种可完成策略 |
| 节奏 | 记录无操作空等、重复点击和请求遗漏；分析空等是否有可读原因或可推进入口 |
| 重玩 | 观察复盘后是否自愿再开同关、尝试不同顺序；询问想改变哪次决定 |
| 性能 | 在明确标注配置的普通集显设备测 1080p 均衡画质，先以稳定 30 fps 为底线，再依设备设更高目标 |
| 稳定 | 完整班次、切后台、刷新继续、回放往返、反复切关与画质；无不可恢复卡死或持续资源增长 |
| 界面 | 1280×720 / 1024×768 / 390×844 的关键许可、事件和确认操作可见且可点 |

保留现有 108 项逻辑回归作为基础。新教学、恢复与路线功能增加针对状态转换和资源一致性的测试；测试数量不能代替真人可玩性结论。

## 8. 下一次代码迭代的具体范围

第一批围绕一个完整班次交付：

1. 版本化活动班次存档、继续入口、后台暂停和统一设置基础。
2. 第一段真正的互动训练，包含一个独立判断步骤。
3. 一个正式班次的接班简报、阶段进度和更明确的收班反馈。
4. 基础声音分组与一套机场环境/飞机声音样板。

这一批验收后，再推广三段教学、六个主题班次和整座机场的美术质量。路线比较作为随后最优先的策略扩展。

## 9. 画面成品感专项：结合最近验收截图

最近的白昼机坪与运行窗口跟随截图已经可以读出飞机、机场和工作台，但主视觉仍有明显的程序化场景感。以下观察来自最近验收图，不使用最初截图代表当前版本。

### 当前画面的具体问题

1. 白昼 1440×900 样图中，中央三维区域约占整屏 42%；固定三列和底部操作区很重。画面内又有大量空机坪/草地，飞机虽然被选中，视觉占比仍偏小。
2. 草地、道面、天空都较平，近处和远处的色彩/细节层级不足。飞机投影较显眼，但表面反光和接地细节没有形成同等层次。
3. 航站楼是长条重复结构，玻璃和混凝土层次较少；远景建筑与树列的分布显得规则，机场缺乏明确地域身份。
4. 大面积机坪主要靠细接缝表达材质，滑行道边缘与标线较整齐；缺少轮迹、使用频率差异、修补与局部污渍形成的尺度线索。
5. 跟随画面的大选中圆环和亮色节点比较抢眼；状态标签、天气卡和场景 HUD 同时争夺注意力。
6. 飞机已有发动机、起落架与姿态，但近景机鼻/座舱、翼面厚度和材质过渡仍需制作标准。

### 美术方向

采用「清晰的机场写实」：真实比例与运行标识，克制的材质细节，冷暖分明且不过曝的光照，低干扰的管制界面。虚构的 Kestrel 机场和航空公司形成统一识别。

白昼：偏中性的道面、较自然的低饱和草地、清晰白色机身与有层次的天空。黄昏：暖直射光与偏冷阴影。夜间：以跑道/滑行道引导灯、机坪灯和航站楼灯形成空间，维持飞机与标线的可读性。

### 视觉修改顺序

| 优先级 | 修改 | 可见效果与验收 |
| --- | --- | --- |
| P0 | 主场景与镜头构图：可收起工具、精简底部卡、加入专注视图；重新调塔台与跟随焦点 | 桌面专注视图以场景约 60–70% 为设计起点；保持待办、许可和重要限制可达。选中机不被大面积空地压小 |
| P0 | 光照与色阶：校准现有曝光、太阳/天空补光、阴影覆盖和环境反射 | 白机不泛灰或过曝，机腹/轮胎有细节，近远景分层；白昼和黄昏使用相同材质仍一致 |
| P0 | 主机坪与跑道材质样板：混凝土/沥青差异、细微粗糙度/法线、轮迹和标线磨损 | 近景能读出材质，远景不变成重复噪点；纹理保持真实尺度，滑行道边界仍清楚 |
| P1 | 一架飞机的完整样板：优先 A320，修轮廓、座舱、翼面、吊架、轮胎与涂装 | 塔台/跟随/俯瞰均易辨认；动画、拾取、合批与接地保持正确，再推广其他机型 |
| P1 | 主航站楼和机场层次：玻璃反射、梁柱/入口、连接合理的登机桥、标牌与道路 | 建筑和机位看得出用途，近中远景具有尺度，避免均匀摆满重复道具 |
| P1 | 视觉反馈：缩小/淡化选中环，标签分级和避让，规划节点仅在相关操作中强调 | 选中、待办与危险均能快速识别；不让所有航班和辅助元素同时高亮 |
| P1 | 夜间与活动：有方向的机场灯光、低强度辉光，按阶段联动地勤 | 夜景能直接游玩；推出/入位有可解释的场景变化，暂停与回放同步 |

当前渲染已经启用 ACES 色调映射、软阴影和标准物理材质，不能把再次开启这些开关当作画质提升。重点是光照与材质的协调、纹理尺度、环境反射和构图。材质与色彩管线按 [Three.js 物理材质](https://threejs.org/docs/pages/MeshStandardMaterial.html)及[色彩管理说明](https://threejs.org/manual/pages/color-management.html)核对。

### 第一批视觉交付建议

先完成同一机位的「飞机 + 机坪 + 航站楼 + 光照 + 专注界面」样板，在白昼、黄昏、夜间和俯瞰四个固定视角验收。样板通过后再扩展全机场，避免所有资产一起修改但质量标准仍不统一。

- 对比使用相同模拟时刻、机型位置、视角、分辨率和画质；同时保留完整 UI 图和场景图。
- 检查标线/文字闪烁、地形遮挡、玻璃排序、远处标签拥挤和轮胎接地。
- 对实际目标设备记录帧率、内存、绘制对象和加载体积；高画质增加的细节需要有可见收益。
- 以完整手动班次验证美化后仍能发现请求、读懂阻挡并下达许可。
